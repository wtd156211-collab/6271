# 行级锚定与映射（从 0 实现）

起始环境只有本说明、`samples/**` 和 `.gitignore`，没有任何实现代码。要用 Python 3.13 标准库从零写出行级锚定引擎，以及它生成的单文件 HTML 报告（数据内联、双击即开）：不引第三方库、不加构建步骤。台账改版之后，工单里写的旧行号要能直接换算出新行号，换算不出来就明确标成已删除。

## 一、范围

要做：读入同一份台账的两个版本，按行建立「旧行号 → 新行号」的映射；覆盖完全相同、相似改写、重复行取舍、整段移动、无法锚定这几种情况；把映射写成文本结果，并渲染成一页可核对报告；同一输入跑两遍结果逐字节一致。

不做：不做字符级 diff（不输出改动片段，也不输出行内差异）、不做语法或语义解析（一切按码位比较）、不读 Git 历史、不联网、不读时钟与随机数、不做多文件批量与增量更新、不做交互式编辑。也不要把 `git diff`、`difflib` 之类的现成对齐结果直接当成交付结果，口径一律以第二节为准。

## 二、口径与公式

### 2.1 行与行号

输入按 `\n` 切行，行尾换行不算行内容；空行也占一个行号。行号一律 1 起、按文件顺序编号。比较按码位（Python 的 `str`），不做大小写折叠、空白折叠、全半角转换或 Unicode 归一化；`\r` 当普通字符处理。

### 2.2 候选

旧行 `a` 与新行 `b` 构成候选，当且仅当下面两条之一成立：

- 精确：`a == b`；
- 相似：`min(len(a), len(b)) >= 6` 且 `lev(a, b) * 10 <= 4 * max(len(a), len(b))`。`lev` 是码位级编辑距离，改、增、删各计 1；这条等价于相似度 `1 - lev / max(len) >= 0.6`，阈值取闭区间。

### 2.3 匹配与择优

- 每个旧行最多锚定一个新行，每个新行最多被一个旧行锚定；
- 保序：配对的旧行号与新行号同时严格递增，交叉只允许取一侧——整段搬家的旧行因此不追新位置；
- 在全部合法匹配里按下面的顺序取最优：
  1. 精确配对数 `E` 最大；
  2. 相似配对数 `S` 最大；
  3. 行号差之和 `T = Σ|新行号 - 旧行号|` 最小（邻近优先）；
  4. 仍并列时，按旧行号升序逐个比较新行号，取字典序最小的解。

没有进入匹配的旧行一律记 `deleted`。新行有没有被锚定不影响旧行的输出，也不额外输出新行一侧的结果。

同一行内容在一侧出现多次时不另立规则：候选本来就会成多对多，仍然按上面四级顺序取整体最优——先保序，再让行号差之和最小，最后按新行号序列定序，所以重复的那几份会按先后依次配对，多出来的一侧记 `deleted`。

## 三、状态机与数据结构

- 候选对 `(旧行号, 新行号, 是否精确)`：精确候选由内容分组得到，相似候选由倒排索引得到；任何剪枝都必须保证不漏候选，也不得把非候选算进来。
- 择优是带权保序匹配：状态记 `(E, S, -T)`，按旧行号升序遍历候选，转移时对「新行号更小的已选前缀」取最优，再按 2.3 的顺序比较；序列并列时比新行号序列。
- 收尾把匹配还原成逐旧行的行号或 `deleted`，按旧行号升序输出；全过程不依赖遍历顺序，换一种索引实现也必须得到同一个映射。

## 四、输入输出与文件格式

### 4.1 输入 `samples/pairs/<案例>/old.txt`、`new.txt`

`old.txt` 是改版前的版本，`new.txt` 是改版后的版本，两侧行数可以不同。两个文件都是 UTF-8 无 BOM、LF 换行、末行也有换行；一行一条记录，不预清洗、不折叠空白、不删空行。案例目录名与期望文件名同名。

### 4.2 映射结果 `samples/expected/<案例>.tsv`

每个旧行一行（与 `samples/pairs/<案例>/old.txt` 一一对应），按旧行号升序，形如 `<旧行号>\t<新行号>` 或 `<旧行号>\tdeleted`（制表符分隔）。无表头、无空行、无注释，文件末尾也要有换行。新行号两两不同，并随旧行号严格递增。

### 4.3 报告页

一页自包含 HTML：数据内联在 `<script type="application/json" id="anchor-data">` 里，不 `fetch`、不引用外部资源，双击即开。页面只渲染、不重算，数字全部取自内联数据。要能一眼看出：① 每行的锚定状态（精确 / 相似 / 已删除）；② 旧行号与新行号的对照；③ 汇总数字 `E`、`S`、已删除行数、`T`。

## 五、性能与验收口径

预算（本机、单进程、含页面渲染）：最大样例 `08-scale`（3 万行/侧、约 5.3 MB/侧）完整映射 ≤ 30 s，峰值常驻内存 ≤ 1 GB；构造上「新增 + 删除 + 改写合计不超过两侧行数的 5%、单侧不超过 20 万行、单侧文件不超过 32 MB」的输入，同样口径下 ≤ 60 s。评测不构造大比例改写的对抗输入。

1. 八组样例各跑一遍，映射与同名期望文件逐字节相同（含末尾换行）。
2. 逐条核对：每个锚定的新行号都必须是候选，且两两不同、随旧行号严格递增；`deleted` 表示最优匹配里没有配对，允许该旧行其实有候选（整段移动就是这样）。
3. 确定性：同一输入重复运行结果逐字节一致，不受哈希随机化、时间、locale、环境变量与网络影响。
4. 不硬编码：不得把样例结果或样例文本写进实现，也不得对样例特判；评测会换文件、换规模。
5. 页面：用 `07-mixed` 生成一份，4.3 的元素齐全，文件不引用外部资源、不 `fetch`。
6. 边界：空文件、只有空行的文件、两侧完全相同、完全重写四种输入都要能跑完，不报错、不写坏结果。

测试框架不限（`unittest` 即可），但仓库初始不含测试代码，验收以样例比对为准。

## 六、样例说明

| 样例对 | 规模（旧 → 新） | 覆盖点 |
| --- | --- | --- |
| `pairs/01-insert` | 14 → 17 行 | 纯插入：两处共插 3 行，14 条旧行全部按位移锚定，无删除 |
| `pairs/02-delete` | 16 → 13 行 | 纯删除：旧 4、5、12 行没有候选，标 `deleted`，其余行顺移 |
| `pairs/03-move` | 20 → 20 行 | 整段移动：旧 3、4 行整块搬到后半段；保序取 18 条精确配对，移动的两条标 `deleted` |
| `pairs/04-edit` | 10 → 10 行 | 一行多处修改：E-01 改三处、E-02 改数值仍达阈值（相似锚定），E-03 整句重写后落在阈值外 |
| `pairs/05-dup` | 29 → 20 行 | 大段重复：8 行块重复三次对两次；按序配对，第三份 8 行与末条分册线共 9 行标 `deleted` |
| `pairs/06-rewrite` | 24 → 24 行 | 完全重写：两侧没有任何候选，24 条全部标 `deleted` |
| `pairs/07-mixed` | 16 → 17 行 | 综合小样例：插入、删除、改写、空行、重复行；含相似度恰好 0.6 的边界对 `slot=A17x9` → `slot=B18y4` |
| `pairs/08-scale` | 30000 → 30060 行 | 规模：合成高熵数据，含 300 行插入、240 行删除、160 行改写；没有相似候选，压索引与择优 |

`03-move` 与 `05-dup` 都在验证保序取舍：能保序的一侧优先，会破坏顺序的一侧记 `deleted`。`07-mixed` 是最小可手算样例，建议逐行核对。`samples/notes.md` 是现场记录，只作背景，不作为口径。

## 八、使用方式（实现交付）

```bash
# 输出映射 TSV（旧行号 → 新行号 或 deleted）到文件
python3 -m lineanchor OLD NEW -o mapping.tsv

# 同时生成自包含 HTML 核对报告（数据内联，双击即开）
python3 -m lineanchor OLD NEW -o mapping.tsv --html report.html

# 不加 -o 时 TSV 写到标准输出
python3 -m lineanchor OLD NEW
```

- 库接口：`lineanchor.compute_mapping(old_lines, new_lines)` 返回
  `(mapping, stats)`；`mapping` 每项是新行号（1 起）或 `None`（deleted）。
- 报告示例：`out/07-mixed.html`（由 `07-mixed` 生成）。
- 测试：`python3 -m unittest discover -s tests`。
- 只依赖 Python 3 标准库；无构建步骤。
